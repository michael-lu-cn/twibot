# twibot 需求文档 1.0 —— Cookie 登录 + 推荐 Feed 流（首个 MVP）

> 状态：草稿 v1.0 ｜ 日期：2026-08-28
> 关联文档：[cordis-插件化重构-调研报告.md](./cordis-插件化重构-调研报告.md)（架构依据，本版本是它的 P0/P1 子集 + P2 静态子集）
> 关联项目：`projects/twitter`（旧项目，抓取逻辑与解析函数平移来源）、`projects/twibot`（新项目，本需求落地处）

---

## 1. 背景与目标

用 **Cordis 新架构**（宿主一棵插件树 + 浏览器一棵插件树）从零实现增强 Twitter 客户端的第一个可用功能：

> **用户粘贴自己的 X cookie → 应用保存并检测登录态 → 展示"推荐 Feed 流"（X 首页 ForYou 时间线）推文列表。**

目标不是功能丰富，而是：
1. 打通"新架构能干活"的最短闭环（凭据服务 → 抓取插件 → 存储 → API → Web 双树 UI）；
2. 验证架构关键性质：**删一行 roster 配置对应 UI 消失、fail loud、插件可装卸**；
3. 为后续功能（关注流/搜索/书签/多标签/评论/群组）铺好插件化地基。

## 2. 范围

### 2.1 In Scope（本版本必须交付）

| # | 能力 | 说明 |
|---|---|---|
| FR-1 | Cookie 输入与保存 | Web 页粘贴 Cookie（支持三种格式，见 FR-1），保存到本地文件，可查看状态/清除 |
| FR-2 | 登录态检测 | 保存时轻校验（域名/必需键），可手动"验证"，失败给清晰文案 |
| FR-3 | 推荐 Feed 抓取 | 打开 `x.com/home`（需登录），拦截 **HomeTimeline** GraphQL 响应 + 滚动翻页，解析推文 |
| FR-4 | 推荐 Feed 展示 | 推文卡片列表（作者名/头像、正文、时间、互动数据），可手动"刷新"增量抓取 |
| FR-5 | 限流与错误 | 沿用旧项目预算（页面桶 12s 串行、GraphQL 桶、5min 缓存、429 退避）；`AUTH_FAILED`/`NO_COOKIES`/`RATE_LIMITED` 有明确提示 |
| FR-6 | 架构性质验证 | 双树 Cordis 跑通；浏览器 roster 删一行（如 `ui-feed`）→ 对应 UI 消失；缺依赖 fail loud |

### 2.2 Out of Scope（明确不做，留后续版本）

- 关注列表 / 高级搜索 / 书签 / 评论 / 群组 / 用户多标签（沿用旧项目能力，后续逐个插件化搬入）；
- 多账号切换、登录账号身份解析（`resolveCurrentHandle`）、cookie 自动刷新；
- 浏览器树的**动态** chunk 加载（本版本只做构建期静态 roster）；
- 无头 sync CLI 入口、HMR、`inspect` 自省工具（后续 P3/P4）。

## 3. 架构概要（双树 Cordis）

```
┌─ 宿主进程（Node，一棵 cordis 树）───────────────────────────┐
│ core-store / core-credential / core-session / core-ratelimit │
│ core-page-parser / sync-feed / api-server                    │
│ 启动 → cordis.yml 装配 → assertEntriesActive（fail loud）    │
└───────────────▲──────────────────────────────────────────────┘
                │ HTTP（REST JSON：/api/credential、/api/feed、/api/_stats）
┌───────────────┴──────────────────────────────────────────────┐
│ 浏览器（第二棵 cordis 树）                                    │
│ web-shell（boot/slots/ui-renderer/router/webApi/store）       │
│ ui-auth（cookie 输入视图）→ app.main                          │
│ ui-feed（推荐流视图）→ app.main / app.nav                     │
│ 静态 roster.ts，构建期打包，删一行 = 该 UI 消失               │
└───────────────────────────────────────────────────────────────┘
```

- 两棵树各跑一个 cordis Context；业务状态在浏览器侧放 React-free store（openTabs 不需要，本版本只有凭据状态与 feed 数据缓存）；
- Web 组件零 ctx：数据经 `ctx.webApi`（fetch + `Ok/Err` + `ERROR_HINTS`）与 store 快照到达；
- 抓取服务按"能力缝"三角色收敛：`ctx.session`（通道）/ `ctx.pageParser`（解析）/ `sync-feed`（消费者），provider 可替换（见 §6）。

### 3.1 宿主树 = dsh 形态（后端机制要求，非"用 cordis 做 IoC"）

后端必须按 dsh 的宿主树形态实现，逐条对位 dsh 机制：

| # | dsh 机制 | 本项目的落地要求 |
|---|---|---|
| H1 | **入口薄壳** | `apps/api/bin.ts` 只做"解析 argv → 选 profile → 调 `boot()`"，零业务 import；将来 `apps/cli`（无头同步）、`apps/web`（同进程起树）共享同一 `boot()` |
| H2 | **boot 序列** | 照抄 dsh profile-boot：`loadEnv → composeProfile`（配置合成）→ `Loader.mount(cordis.yml entry 树)` → 每行 entry 动态 import → `inject` 依赖收敛激活 → `assertEntriesActivated`（fail loud：点名每个未激活插件及其缺失服务）→ serve |
| H3 | **动态 import 加载** | 每行 yml 的 `name` 由 Loader 动态 import（ESM/CJS 导出归一化）；换实现 = 改一行 `name`。本轮 config 只做字面量注入，**不做 `!!js` 表达式**（暂无需要，留 HMR 期） |
| H4 | **配置层叠** | 从第一天支持三层：`base bundle patch`（core 服务）→ `profile patch`（api/web/headless 变体）→ `--patch overlay`（命令行）；`--dump-config` 与真实启动**零偏差**（同一个合成函数，禁止两套路径） |
| H5 | **注册皆 effect** | `api-server` 挂路由、`sync-feed` 监听 `sync/pre-execute`、`core-*` provide 服务、`core-session` 管理浏览器进程——全部在 apply 内注册并返回 disposer；卸载按逆序回滚（删一行 = 路由/监听/服务一并消失） |
| H6 | **服务词汇表共享** | `ctx.store / credential / session / ratelimit / pageParser` 是后续所有功能（关注流/搜索/书签/评论/群组）的服务基座；后续功能 = 往同一棵树 insert 插件行，不触碰内核 |
| H7 | **本轮不做的 dsh 面** | `!!js` 动态求值、HMR（watchUserPatches）、`inspect/define/run` 自生长——留 P3/P4；但架构上留好接缝（modules/loader.internal 概念），避免返工 |

## 4. 功能需求

### FR-1 Cookie 输入与保存

- 入口：Web `/`（未配置时自动显示引导视图）。输入框支持粘贴三种格式，前台不做解析，原样 POST：
  1. **Cookie 头字符串**：`auth_token=xxx; ct0=yyy; ...`（DevTools → Network → 请求头里复制 Cookie）；
  2. **cURL 文本**：DevTools → 右键请求 → Copy as cURL（自动识别 `-H 'cookie: ...'` / `-b '...'`）；
  3. **JSON 数组**：`[{"name":"auth_token","value":"...","domain":".x.com",...}]`。
- 保存：`POST /api/credential { cookie: string }` → 解析 → 必需键校验（`auth_token` + `ct0`，域名限 `.x.com`/`twitter.com`）→ 持久化到 `twibot/data/credential.cookie`（原样文本 + 解析对象）→ 返回 `{ ok, status }`。
- 查看/清除：`GET /api/credential/status` 返回 `{ configured, keys, source }`（**不回显 cookie 值**）；`DELETE /api/credential` 删除文件。
- 环境变量兼容：`TWITTER_COOKIES` 存在时优先（与旧项目一致）；`TWITTER_CDP_URL` 直连已登录浏览器仍支持（`source: 'cdp'`）。

### FR-2 登录态检测

- 保存时轻校验：缺少必需键 → 400 `BAD_CREDENTIAL`，列出缺的键；格式无法解析 → 400 提示支持格式。
- 手动"验证"：`POST /api/credential/verify` → 复用 core-session 打开 `x.com/home`，探测正文是否含欢迎/登录墙文案（复用旧项目 `extractCurrentUser`/正文探测逻辑）；有效返回 `{ ok, valid: true }`，失效返回 `{ ok, valid: false, reason: 'AUTH_FAILED' }` 并给出更新 cookie 的引导文案。
- 首次同步时若发现登录墙 → 同步失败并自动标记 `configured` 状态为"失效"（前端状态栏变红）。

### FR-3 推荐 Feed 抓取

- 触发：Web"刷新推荐流"按钮 → `POST /api/feed/sync?limit=20`（limit 默认 20，上限 50）。
- 流程（复用旧项目 tweets 抓取范式）：
  1. `launchSession()`（12s 间隔令牌 + 全局串行锁）；
  2. `page.goto('https://x.com/home')`；
  3. `page.on('response')` 拦截 URL 含 `/graphql/` 且操作名 **`HomeTimeline`** 的响应（ForYou 推荐流；**不匹配 HomeLatestTimeline**）；
  4. 解析 `data.home. timeline 的 instructions[].entries[]`（含嵌套 TimelineTimelineModule 评论容器一律跳过，只取顶层推文条目）；
  5. 滚动翻页 ≤5 轮累积；广告条目（`itemContent.promotedMetadata` 存在）跳过；
  6. 推文用复用函数 `extractTweet`（原文、ISO 时间、互动 metrics、作者 core/legacy 兼容）解析；DOM fallback（`extractDomTweet`）兜底；
  7. 增量落库：`tweets` upsert（作者 userId）+ `users` upsert（作者资料）+ `feed` 表按 position 时间轴插入（见 §5）；新增数 `added`。
- 响应：`{ ok, data: { added, tweets: Tweet[], syncedAt }, source: 'sync' }`。

### FR-4 推荐 Feed 展示

- `GET /api/feed?limit=20` → 本地读：`feed JOIN tweets LEFT JOIN users`，按 `feed.position DESC`。
- 每卡片展示：作者头像 + 名字 + `@handle`、正文、相对时间、回复/转推/点赞/浏览数；点击卡片暂无动作（评论面板后续版本）。
- 「同步时间」+「刷新」按钮；未同步过 → 空态引导"请先同步"。
- Web 状态栏：cookie 状态（未配置 / 有效 / 失效）+ 可切换"设置 cookie"视图随时重粘。

### FR-5 限流与错误

- 预算沿用旧项目：页面会话 12s 间隔 + 全局串行、结果缓存 5min、429 退避重试 2 次、队列等待上限 90s；
- `GET /api/_stats` 保留（令牌余量、近期调用数、缓存大小）；
- 错误码统一：`NO_COOKIES` / `AUTH_FAILED` / `BAD_CREDENTIAL` / `RATE_LIMITED` / `SCRAPE_FAILED` / `NOT_SYNCED`，前端经 `ERROR_HINTS` 渲染可操作提示。

### FR-6 架构性质验证（本版本的隐性验收项）

- 宿主树 `--dump-config` 与真实启动一致；
- 浏览器 roster 删 `ui-feed` 行 → 首页只剩空态（无脚本报错）；加回 → 恢复；
- 故意把 `sync-feed` 的 inject 依赖弄缺 → 启动失败并列出缺失服务名（fail loud），不允许半可用。

## 5. 数据模型（SQLite，沿用 Drizzle + better-sqlite3）

现有 8 表复用 3 张 + 新增 1 张：

| 表 | 用途 | 本版本动作 |
|---|---|---|
| `users` | 作者资料（X userId 主键） | 复用（`upsertUser`） |
| `tweets` | 推文内容（X id 主键，含 metrics） | 复用（`upsertTweet`，userId = 作者 id） |
| `app_kv` | 键值（feed 最后同步时间等） | 复用 |
| **`feed`（新增）** | 推荐流条目：`tweet_id TEXT PK`、`position INTEGER`、`fetched_at INTEGER` | 用 position 时间轴策略（首次锚定 100000、更旧递减、增量更新递增，复用 `position.ts`） |

> 不新建正文副本：feed 只存"哪些推文在流里"的排序，内容 JOIN tweets/users——与旧项目 bookmarks 的形态一致，避免重复存储。

## 7. API 契约（前缀 `/api`）

| 方法与路径 | 请求 | 成功 | 失败 |
|---|---|---|---|
| `POST /api/credential` | `{ cookie: string }` | `{ ok:true, data:{ configured:true, keys:['auth_token','ct0'] } }` | 400 `BAD_CREDENTIAL`（缺键/无法解析） |
| `GET /api/credential/status` | — | `{ ok:true, data:{ configured:boolean, keys:string[], source:'cookie'\|'cdp'\|'none' } }` | — |
| `DELETE /api/credential` | — | `{ ok:true, data:{ deleted:true } }` | — |
| `POST /api/credential/verify` | — | `{ ok:true, data:{ valid:true } }` | 200 `{ valid:false, reason:'AUTH_FAILED' }`；无凭据 401 `NO_COOKIES` |
| `POST /api/feed/sync` | `?limit=20` | `{ ok:true, data:{ added, tweets, syncedAt }, source:'sync' }` | 401 `NO_COOKIES`/`AUTH_FAILED`、429 `RATE_LIMITED`、502 `SCRAPE_FAILED` |
| `GET /api/feed` | `?limit=20` | `{ ok:true, data:{ tweets, syncedAt }, source:'database' }` | 404 `NOT_SYNCED` |
| `GET /api/_stats` | — | 令牌桶/调用/缓存状态 | — |

错误信封统一 `{ ok:false, error:{ code, message } }`；成功信封 `{ ok:true, data, source, elapsedMs }`（沿用旧项目约定，前端 `isOk` 判别）。

## 8. 抓取策略要点（HomeTimeline）

- **不维护 operation hash**：拦截 X 页面自己发出的 HomeTimeline 请求（旧项目已验证"页面拦截"路线，X 改版只影响解析函数，fallback 到 DOM）；
- 拦截条件：`url.includes('/graphql/') && url.includes('HomeTimeline') && !url.includes('HomeLatestTimeline')`；
- 解析入口：`data.home` 的 timeline instructions（若字段路径变化，先查响应再适配并更新文档）；
- 广告过滤：`itemContent?.promotedMetadata` 存在即跳过；
- 登录墙检测：正文含 `Don't miss what's happening` / `New to X` / URL 含 `/i/flow/login` → `AUTH_FAILED`（复用旧项目文案）；
- 限流优先：页面路径（浏览器行为，容忍度高）；GraphQL 直调留后续"关注流"用。

## 9. 验收标准（可机械判定）

| # | 验收项 | 判定 |
|---|---|---|
| A1 | 无凭据首访 | Web `/` 显示"设置 cookie"引导视图，无脚本报错 |
| A2 | 粘贴合法 cookie | 保存成功；状态"有效"；`data/credential.cookie` 落盘 |
| A3 | 粘贴缺键 cookie | 400 且提示缺 `auth_token`/`ct0` |
| A4 | 同步推荐流 | `POST /api/feed/sync` 返回 ≥1 条（含作者名/正文/时间/互动）；页面出现推文卡片列表 |
| A5 | 重复同步 | 第二次 `added` 大小与新增一致（无新增则 0）；页面列表不重复 |
| A6 | 无效 cookie | 同步返回 `AUTH_FAILED`，前端状态栏标红并给出更新引导 |
| A7 | 限流保护 | 连按两次刷新 ≤12s 间隔被串行等待或返 `RATE_LIMITED` 文案（`_stats` 可见） |
| A8 | 删行即消失 | 浏览器 roster 删 `ui-feed` → 首页不再渲染 feed（其余 UI 正常） |
| A9 | fail loud | `sync-feed` 注入依赖缺失时启动失败并列出缺失服务名 |
| A10 | dump 一致 | `--dump-config` 输出与真实启动插件集合一致 |
| A11 | 入口薄壳（H1） | `apps/api/bin.ts` 不含任何业务代码（仅 argv/profile/boot）；功能全部由树内插件提供，改入口零业务 |
| A12 | 宿主删行（H5） | cordis.yml 删 `sync-feed` 行 → `POST /api/feed/sync` 404，`/api/credential`、`/api/_stats` 等其他端点不受影响（注册皆 effect 可逆） |
| A13 | 换实现（H3） | 把某个插件行的 `name` 指向另一个实现（如 core-session 换成 cdp 版）→ 全站行为切换，消费者插件零改动 |
